# CdrJobs v1.0.3 — Hunter Configurability Hotfix

## Goal
Make Hunter progression configurable for both mobs and PvP without reopening easy XP farming.

## New Hunter settings

```yaml
hunter:
  allow-unlisted-mobs: true
  fallback-mob-xp: 3
  pvp:
    enabled: true
    xp: 10
    count-toward-trials: true
    same-victim-cooldown-seconds: 300
```

## Behavior
- Listed mobs use values from `hunter.xp`.
- If `allow-unlisted-mobs: true`, unlisted mobs use `fallback-mob-xp`.
- If `allow-unlisted-mobs: false`, only mobs explicitly listed in `hunter.xp` grant Hunter progression.
- Player kills grant Hunter XP only when `hunter.pvp.enabled: true`.
- PvP XP is controlled by `hunter.pvp.xp`.
- `count-toward-trials` decides whether rewarded player kills increment Hunter Trial kill counters.
- The same killer cannot repeatedly receive a PvP reward from the same victim until `same-victim-cooldown-seconds` expires.
- PvP cooldown state persists through server restarts using the existing cooldown table.

## Regression testing
1. Listed mob grants its configured XP.
2. Unlisted mob grants fallback XP when allowed.
3. Unlisted mob grants no XP when whitelist mode is enabled (`allow-unlisted-mobs: false`).
4. Player kill grants PvP XP when enabled.
5. Re-killing the same player during cooldown grants no second reward.
6. A different victim can still reward the killer.
7. Restart server and confirm the same-victim cooldown still blocks farming.
8. Disable `hunter.pvp.enabled` and confirm player kills give no Hunter XP.
9. Spawner/breeding exclusions still work.
10. `/cdrjobsadmin reload` applies Hunter config changes without a full restart.

## Database
No schema migration. Schema remains `9`.
