# CdrJobs v0.1.2 — Runebound Tempering

**Chapter:** Runebound Delver / Miner Stability & Balance

This update deliberately avoids adding another large progression layer. Its purpose is to make the Miner implementation safe, configurable and reusable as the reference architecture for Farmer, Hunter, Lumberjack and Fisher.

## Fate Essence hardening

A new `fate_milestone_claims` SQLite table records milestone rewards permanently per player and job.

Why this matters:
- A milestone reward can only be claimed once.
- Lowering a level and raising it again cannot generate duplicate Fate Essence.
- Existing v0.1.0/v0.1.1 players are backfilled on startup. Milestones at or below their current level are treated as already claimed.
- Fresh players still receive the normal rewards when they reach those milestones naturally.

## Configurable XP curve

The level formula is now configurable:

```text
required XP = base + linear*(level-1) + quadratic*(level-1)^2
```

Default values:
```yaml
settings:
  xp-curve:
    base-xp: 100
    linear-growth: 0
    quadratic-growth: 15
```

These defaults preserve the original CdrJobs curve exactly.

Miner also has a global tuning value:
```yaml
miner:
  xp-multiplier: 1.0
```

This lets a server make Miner progression globally slower/faster without rewriting every ore XP value.

## Anti-exploit hardening

### Piston movement
A player-placed tracked ore keeps its placed status when moved by a piston or sticky piston. Both extension and retraction are tracked.

### Explosion cleanup
If TNT, creepers or block explosions destroy a tracked placed ore, its stale coordinate is removed from SQLite.

### Existing protection
Breaking a player-placed ore still grants:
- no Miner XP
- no Trial progress
- no Echo progression

## QoL
`/cdrjobs stats` now displays the next Fate Essence milestone and its reward.

The max-level actionbar also respects the configured max level instead of assuming Lv.100.

## Upgrade behavior
No manual database migration is required. New tables are created automatically. Existing progress, skills, Fate Essence, Trials and cooldowns remain intact.

## Recommended server test checklist
- Upgrade an existing v0.1.1 database and confirm player data remains intact
- Confirm existing high-level players do not receive old Fate milestone rewards again
- Reach a new Fate milestone naturally and confirm it rewards exactly once
- Lower/re-raise a level with admin commands and verify the same milestone cannot reward twice
- Place an ore, move it with a piston, then break it and verify no XP/Trial progress is given
- Test sticky-piston retraction with a placed ore
- Destroy placed ores with TNT/creeper and confirm no stale tracking behavior appears later
- Change `miner.xp-multiplier` and reload to verify tuning applies immediately
- Change XP curve values and reload to verify next-level requirements update immediately
