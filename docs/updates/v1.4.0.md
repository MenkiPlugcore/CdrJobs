# CdrJobs v1.4.0 — Profession Contracts

## Goal
Add lightweight repeatable Daily and Weekly objectives without turning CdrJobs into a heavy quest engine.

## Commands
- `/cdrjobs contracts`
- `/cdrjobs contracts claim <daily|weekly>`
- `/cdrjobs contracts reroll <daily|weekly>`

## Progress source
Contracts listen to `ProfessionActionEvent`. This is intentional: the event is fired only after CdrJobs profession anti-exploit checks accept the action. Placed ores/logs, blocked Hunter kills, Fisher AFK catches, and other rejected activity therefore must not advance Contracts.

## Cycle behavior
Default timezone is `Asia/Jakarta`.
- Daily resets when the local calendar day changes.
- Weekly resets on Monday in the configured timezone.
- Assignment is deterministic from UUID + cadence + cycle + reroll salt.
- Relog/restart does not randomly change the assigned Contract.

## Reroll safety
Default:
```yaml
contracts:
  daily-rerolls: 1
  weekly-rerolls: 1
```

Reroll:
- chooses an alternate definition when available,
- resets progress to zero,
- consumes the cadence reroll allowance,
- cannot be used after a Contract is complete or claimed.

## Custom definitions
Admins can add/remove definitions below `contracts.definitions` and apply changes with `/cdrjobsadmin reload`.

Example:
```yaml
contracts:
  definitions:
    custom-hunter-daily:
      name: "Night Patrol"
      cadence: DAILY
      job: HUNTER
      target: 100
      reward-xp: 1000
      reward-fate: 0
```

Supported cadence values: `DAILY`, `WEEKLY`.
Supported jobs: `MINER`, `FARMER`, `HUNTER`, `LUMBERJACK`, `FISHER`.

## Default reward philosophy
Daily Contracts reward profession XP only. Weekly Contracts reward more XP plus one Fate Essence. Fate remains intentionally scarce.

If the selected profession is already Lv.100, contract XP flows through normal progression and therefore into Profession Mastery.

## Persistence
Contract state is stored in the existing `profession_counters` table under the internal `CONTRACTS` namespace. No new table or schema migration is required; schema remains `9`.

## Regression checklist
1. Open `/cdrjobs contracts` twice and confirm assignment does not change.
2. Restart and confirm assignment/progress persist.
3. Perform valid Miner/Farmer/Hunter/Lumberjack/Fisher actions and verify only matching assigned Contracts progress.
4. Verify blocked anti-exploit actions do not progress Contracts.
5. Complete a Daily Contract and claim once; verify second claim is rejected.
6. Verify Daily XP reward reaches normal progression or Mastery at Lv.100.
7. Complete a Weekly Contract and confirm configured Fate reward is added once.
8. Reroll an incomplete Contract and verify progress resets and assignment changes.
9. Attempt a second reroll past the configured allowance and verify rejection.
10. Attempt reroll after completion/claim and verify rejection.
11. Change timezone/cycle in a test environment and verify Daily/Weekly rollover resets state.
12. Add a custom definition, reload, and verify it becomes eligible without restart.
13. Verify all Contract placeholders.
14. Re-run Mastery, Rebirth, Profile, leaderboard, and Five Paths regression tests.
