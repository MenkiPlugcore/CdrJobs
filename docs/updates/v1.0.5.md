# CdrJobs v1.0.5 — Admin & Debug Tools

## Goal
Make production testing and support safer without requiring direct SQLite edits.

## New commands
- `/cdrjobsadmin addessence <player> <amount>`
- `/cdrjobsadmin setessence <player> <amount>`
- `/cdrjobsadmin resetjob <player> <job>`
- `/cdrjobsadmin resettrial <player> <job>`
- `/cdrjobsadmin resetcooldown <player> <job>`
- `/cdrjobsadmin export <player> [file|console|both]`

## Inspect improvements
`/cdrjobsadmin inspect <player>` now shows Fate Essence, all five profession levels/XP/ranks, counters, trial flags, Miner trial state, skill ranks and persistent cooldowns.

## Reset behavior
### resetjob
Resets only the selected profession:
- level/XP
- profession skill ranks
- profession trial state/counters
- profession cooldowns

Global Fate Essence and all other professions remain intact. The Fate milestone claim ledger is deliberately preserved so resetting a profession cannot be used to earn the same milestone Essence a second time.

### resettrial
- Miner: resets Miner trial data only.
- Farmer/Hunter/Lumberjack/Fisher: Trial progress now uses an internal reset baseline.
- Lifetime activity counters are preserved after a Trial reset.
- Only Trial progress and `trial_*` completion flags restart from zero.
- Hunter lifetime `mob_kills` and `pvp_kills` therefore remain intact after `/resettrial`.

The reset baseline is stored inside the existing generic profession counter storage, so there is no database schema migration.

### resetcooldown
Clears persistent cooldown records for the selected profession. Hunter PvP same-victim cooldown records use the Hunter prefix and are included.

## Debug export
Default target directory: `plugins/CdrJobs/debug/`.

The report contains version/schema, UUID, Fate Essence, all five profession snapshots, lifetime counters, flags, Miner trial progress, skills, cooldown timestamps and latest Hunter decision. Internal Trial reset baselines are intentionally hidden from normal counter output.

`console` logs the report; `both` writes a file and logs it.

## Hardening added during candidate review
- `resetjob` preserves Fate milestone claims to prevent repeat Essence farming.
- `resettrial` no longer destroys lifetime profession statistics.
- Trial completion checks for Farmer, Hunter, Lumberjack and Fisher now use reset-aware progress instead of lifetime totals.
- Existing players require no migration; a missing baseline behaves as zero.

## Test checklist
1. Add/set Fate Essence and verify `/inspect`.
2. Reset one Job and confirm other professions and global Essence remain unchanged.
3. Re-level a reset Job through an already-earned Fate milestone and confirm the milestone does not reward Essence again.
4. Record lifetime profession counters, run `/resettrial`, and verify those lifetime counters remain unchanged.
5. After `/resettrial`, perform one activity and confirm the Trial starts from `1`, not from the old lifetime total.
6. Hunter: verify `mob_kills` and `pvp_kills` survive Trial reset.
7. Complete a Trial again after reset and confirm its `trial_*` flag can be earned normally.
8. Reset cooldown and verify the selected persistent cooldown is cleared.
9. Export to file and console without exceptions.
10. Restart server and confirm Trial baselines and untouched data remain persistent.
11. Re-run the five-profession regression matrix.

## Database
No schema migration. Schema remains `9`.
