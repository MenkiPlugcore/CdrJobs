# CdrJobs v1.0.5 — Admin & Debug Tools

## Goal
Make production testing and support safer without requiring direct SQLite edits.

## New commands
- `/cdrjobsadmin addessence <player> <amount>`
- `/cdrjobsadmin setessence <player> <amount>`
- `/cdrjobsadmin resetjob <player> <job>`
- `/cdrjobsadmin resettrial <player> <job>`
- `/cdrjobsadmin resetcooldown <player> <job>`
- `/cdrjobsadmin export <player> [file|console|both]`

## Inspect improvements
`/cdrjobsadmin inspect <player>` now shows Fate Essence, all five profession levels/XP/ranks, counters, trial flags, Miner trial state, skill ranks and persistent cooldowns.

## Reset behavior
### resetjob
Resets only the selected profession:
- level/XP
- profession skill ranks
- profession trial state/counters
- profession cooldowns

Global Fate Essence and all other professions remain intact. The Fate milestone claim ledger is deliberately preserved so resetting a profession cannot be used to earn the same milestone Essence a second time.

### resettrial
- Miner: resets Miner trial data only.
- Farmer/Hunter/Lumberjack/Fisher: profession counters are also their Trial progress source, so counters and flags are cleared together.

### resetcooldown
Clears persistent cooldown records for the selected profession. Hunter PvP same-victim cooldown records use the Hunter prefix and are included.

## Debug export
Default target directory: `plugins/CdrJobs/debug/`.

The report contains version/schema, UUID, Fate Essence, all five profession snapshots, counters, flags, Miner trial progress, skills, cooldown timestamps and latest Hunter decision. `console` logs the report; `both` writes a file and logs it.

## Test checklist
1. Add/set Fate Essence and verify `/inspect`.
2. Reset one Job and confirm other professions and global Essence remain unchanged.
3. Re-level a reset Job through an already-earned Fate milestone and confirm the milestone does not reward Essence again.
4. Reset one Trial and confirm intended Trial progress clears.
5. Reset cooldown and verify the selected persistent cooldown is cleared.
6. Export to file and console without exceptions.
7. Restart server and confirm untouched data remains persistent.
8. Re-run the five-profession regression matrix.

## Database
No schema migration. Schema remains `9`.
