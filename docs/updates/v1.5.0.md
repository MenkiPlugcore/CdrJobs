# CdrJobs v1.5.0 — Fate Resonance

`Fate Resonance` is a derived cross-profession prestige/status layer. It intentionally does not create a second progression database or duplicate Level/Mastery state.

## Core rules

A Resonance definition pairs exactly two professions.

- `RESONANT`: both professions meet `min-level`.
- `HARMONIZED`: the pair is Resonant and both professions meet `harmonized-mastery-tier`.
- Resonance is recalculated from canonical Job Level + Mastery every time it is read.
- Resetting/lowering a profession can immediately lock a previously unlocked Resonance.
- Rite of Rebirth does not alter Resonance because it does not alter Job Level or Mastery.
- No database schema migration; schema remains `9`.

## Default pairings

1. Earthbound — Miner + Lumberjack
2. Groveborn — Farmer + Lumberjack
3. Cave Stalker — Miner + Hunter
4. Deep Predator — Hunter + Fisher
5. Abyss Delver — Miner + Fisher
6. Wildborn — Hunter + Farmer
7. Tide Gardener — Farmer + Fisher
8. Iron Harvest — Miner + Farmer
9. Timber Tide — Lumberjack + Fisher
10. Wildwood — Hunter + Lumberjack

Defaults use Level 50 for Resonant and Mastery I on both professions for Harmonized.

## Player commands

- `/cdrjobs resonance`
- `/cdrjobs resonance <id>`
- alias `/cdrjobs fateresonance <id>`

The list view shows current level progress, unlocked count, Harmonized count, and Resonance Score. Score is intentionally simple: +1 per Resonant pair and another +1 when Harmonized.

## Admin diagnostics

- `/cdrjobsadmin diagnose` reports whether Resonance is enabled and how many valid definitions loaded.
- `/cdrjobsadmin inspect <player>` includes unlocked/Harmonized counts and Resonance Score.
- `/cdrjobsadmin resonancedebug <player>` prints every configured pair with Level/Mastery inputs and resolved state.
- debug export includes Resonance counts, score, and unlocked names.

## PlaceholderAPI

Global/profile placeholders:

- `%cdrjobs_resonance_unlocked%`
- `%cdrjobs_resonance_harmonized%`
- `%cdrjobs_resonance_score%`
- `%cdrjobs_resonance_names%`
- `%cdrjobs_resonance_harmonized_names%`
- `%cdrjobs_profile_resonance_unlocked%`
- `%cdrjobs_profile_resonance_harmonized%`
- `%cdrjobs_profile_resonance_score%`

Per definition (`<id>` = `earthbound`, `groveborn`, etc.):

- `%cdrjobs_resonance_<id>_unlocked%`
- `%cdrjobs_resonance_<id>_harmonized%`
- `%cdrjobs_resonance_<id>_status%`
- `%cdrjobs_resonance_<id>_display%`
- `%cdrjobs_resonance_<id>_title%`
- `%cdrjobs_resonance_<id>_badge%`

## Custom definitions

```yaml
fate-resonance:
  enabled: true
  definitions:
    earthbound:
      enabled: true
      name: "Earthbound"
      title: "Earthbound"
      badge: "✦"
      jobs: [MINER, LUMBERJACK]
      min-level: 50
      harmonized-mastery-tier: 1
```

Definitions are reread from config, so `/cdrjobsadmin reload` can change names, titles, badges, requirements, enabled state, or pair composition without a database migration.

## Balance policy

v1.5.0 intentionally does **not** add direct damage, defense, gathering speed, drop-rate, XP multiplier, or economy multiplier from Resonance. The system is a prestige/status layer and a clean integration point for later optional systems.

## Regression checklist

1. Set two paired Jobs below requirement: state must be LOCKED.
2. Raise only one Job to requirement: still LOCKED.
3. Raise both to requirement: state becomes RESONANT immediately.
4. Raise both to required Mastery: state becomes HARMONIZED immediately.
5. Lower/reset one Job: state locks immediately; no stale state survives.
6. Run Rite of Rebirth: state remains unchanged when Level/Mastery remain unchanged.
7. Restart server: same canonical values must produce identical Resonance state.
8. Test all ten default pairings.
9. Test global and per-definition PlaceholderAPI values.
10. Disable one definition + reload: it must disappear from command/debug calculations.
11. Add invalid or duplicate pair definitions: validator must warn without crashing plugin enable.
12. Re-run Contracts, Mastery, Rebirth, Five Paths progression and anti-exploit regression checks.
