# CdrJobs v1.2.0 — Rite of Rebirth

## Goal
Allow players to rebuild one profession's skill tree without deleting the profession itself or creating a Fate Essence refund exploit.

## Player flow
- `/cdrjobs rebirth`
- `/cdrjobs rebirth <miner|farmer|hunter|lumberjack|fisher>`
- `/cdrjobs respec [job]`

The first GUI shows all five professions and their current invested ranks, estimated refund, fee, and cooldown state. Selecting a profession opens a second confirmation GUI before any data is changed.

## What Rebirth resets
Only purchased skill ranks for the selected profession.

## What Rebirth preserves
- Job level
- Job XP
- Trial progress/completion
- lifetime profession counters/statistics
- Fate milestone claim ledger
- active-ability cooldowns
- every other profession

This separation is intentional. Rebirth is a build-respec feature, not a progression reset.

## Refund calculation
Refund is derived from the skill ranks that currently exist in `player_skills` and the canonical `essenceCost` declared by each skill enum.

Default:
```yaml
rite-of-rebirth:
  refund-percent: 100
```

Runtime clamps refund percentage to `0..100`.

## Persistent cooldown
Default cooldown is seven days:
```yaml
rite-of-rebirth:
  cooldown-seconds: 604800
```

The cooldown is stored using the existing `ability_cooldowns` table with a dedicated `rebirth_<job>` key, so it survives full server restarts without a schema migration.

Normal `/cdrjobsadmin resetcooldown` clears active-ability cooldowns only and deliberately does not remove Rebirth cooldowns.

## Fee modes
```yaml
rite-of-rebirth:
  fee:
    mode: NONE
    fate-essence: 0
    vault: 0.0
```

Supported modes:
- `NONE` — no fee.
- `FATE` — requires the configured existing Fate Essence balance before the transaction.
- `VAULT` — charges the configured economy amount through an optional Vault provider.

Vault is not a hard dependency. CdrJobs resolves the economy service reflectively. When `VAULT` mode is selected but Vault/provider is unavailable, the Rebirth is rejected safely.

If a Vault withdrawal succeeds but the SQLite Rebirth transaction fails, CdrJobs attempts to deposit the charged amount back.

## Transaction safety
Skill deletion, Fate refund/Fate fee, and persistent Rebirth cooldown are executed in one SQLite transaction.

This protects against:
- double-clicking the confirm button
- repeated packet/UI confirmation
- partial refund with skills still present
- skills deleted without Fate refund
- restart-based cooldown bypass

A second confirm after a successful transaction sees no purchased ranks and therefore cannot refund again.

## Admin command
`/cdrjobsadmin forcerespec <player> <job>`

Admin force-respec:
- bypasses Rebirth cooldown
- bypasses configured fee
- returns 100% of invested Fate Essence
- still preserves level/XP/Trial/statistics/milestone claims

## Compatibility
- Java 21
- Paper API 1.21.4 compile target / Paper 1.21.x runtime family
- PlaceholderAPI remains optional
- Vault remains optional
- schema stays `9`

## Regression checklist
1. Buy several skill ranks in Miner and note Fate Essence, level, XP, Trials, and ability cooldown.
2. Run `/cdrjobs rebirth miner`, review the quote, cancel once, and verify nothing changes.
3. Confirm Rebirth and verify all Miner skill ranks become zero.
4. Confirm the expected Fate Essence refund is returned exactly once.
5. Verify Miner level and XP are unchanged.
6. Verify Miner Trial progress/completion is unchanged.
7. Verify Miner normal ability cooldown is unchanged.
8. Re-open Rebirth immediately and verify the persistent cooldown blocks another respec.
9. Restart the server and verify the Rebirth cooldown still blocks the profession.
10. Repeat the same skill reset check for Farmer, Hunter, Lumberjack, and Fisher.
11. Double-click/spam the final confirm item and verify refund occurs once only.
12. Set `refund-percent: 50`, reload, buy known ranks, and verify the quote/refund uses 50%.
13. Set fee mode `FATE`, configure a fee, and verify insufficient balance rejects without deleting skills.
14. Set fee mode `VAULT` without Vault installed and verify Rebirth rejects safely while CdrJobs still boots normally.
15. With Vault + economy installed, verify insufficient funds, successful charge, and refund behavior.
16. Run `/cdrjobsadmin forcerespec <player> <job>` and verify fee/cooldown bypass with correct refund.
17. Re-run Adventurer Profile and confirm unlocked skill/awakened counts update after Rebirth.
18. Re-run all five profession progression/anti-exploit tests from the release regression matrix.

## Database
No new table or schema migration. Schema remains `9`.
